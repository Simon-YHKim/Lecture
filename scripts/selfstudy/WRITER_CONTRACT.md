# 자습 교재 집필 계약서

너는 사내 AutoCAD 영상 강의를 **강사 없이 혼자 학습하는 교재**로 다시 쓴다.
결과는 HTML 이 아니라 **JSON 콘텐츠 파일 하나**다. 렌더링은 빌더가 한다.

---

## 1. 무엇이 사라졌고 무엇으로 메우는가

원본은 셋에 기대고 있었다. 자습본에는 셋 다 없다.

| 사라진 것 | 자습본이 대신 놓는 것 |
| --- | --- |
| 내레이터 목소리 (억양·강조·되묻기) | 짧은 문장, `note` 블록, 해요체로 던지는 되묻기 |
| 순차 등장하는 화면 모션 | `cards` · `table` · `figure`(인라인 SVG) |
| 29곳의 실시간 화면 녹화 | `steps` 블록 — 명령·입력값·기대 결과·막혔을 때 |

**빠뜨리면 안 되는 것**: 영상에서 화면이 보여 주던 정보. 대본 문장에 없더라도
학습자가 그것 없이는 따라 할 수 없으면 글이나 그림으로 반드시 채운다.

---

## 2. 문체 — 이것이 이번 요청의 핵심 조건이다

### 국문

**합쇼체 70~80% · 해요체 20~30%.** 기계적으로 검사한다(`tone_check.py`).
현재 원본 대본은 합쇼체 96%다. 그러니 **의식적으로 해요체를 넣어야** 통과한다.
대략 **네 문장 중 한 문장**이 해요체다.

| 여기는 합쇼체 | 여기는 해요체 |
| --- | --- |
| 정의·규격·치수·레이어 값 | 되묻기 — 「왜 그럴까요?」 「여기서 헷갈리시죠?」 |
| 조작 절차의 지시문 | 부연·완충 — 「…거든요.」 「…면 돼요.」 「…예요.」 |
| 검산 판정, 시험 안내 | 격려·페이스 — 「천천히 가도 괜찮아요.」 「여기서 한 번 쉬어 가요.」 |
| 사실 진술 | 자습자에게 말 거는 대목 — 「막히면 이 절로 돌아오세요.」 |

**금지**
- 문어체 종결(`~한다` · `~이다` · `~않는다`). 하나라도 있으면 검사가 FAIL 한다.
- 번역투: `~에 대해` · `~을 통해` · `~에 있어서` · `가지고 있다` · `~되어진다`.
- 한 문장 40자 초과. 접속사로 이어 붙이지 말고 끊는다.
- 이모지.

### 영문

- 평이한 기술 영어. 절차는 명령형(`Type UCS and press Enter.`).
- 국문을 직역하지 않는다. **같은 사실을 영어 화자가 쓰는 방식으로** 다시 쓴다.
- 용어는 `curriculum.json` 의 `glossary` 를 그대로 따른다. 새 역어를 만들지 않는다.
- 국문에 해요체로 넣은 되묻기·격려는 영문에서도 같은 자리에 둔다.
  영어에는 문체 비율 요건이 없으니 자연스러운 2인칭 구어로 쓴다.
- 문장은 20단어 안쪽.

### 두 언어의 관계

모든 `{"ko":…, "en":…}` 쌍은 **같은 사실을 담는다.** 한쪽에만 있는 정보가 있으면 안 된다.
길이가 크게 어긋나도 안 된다(한쪽이 두 배를 넘으면 다시 쓴다).

---

## 3. 사실 충실도

1. **명령·입력값은 한 글자도 바꾸지 않는다.** `UCS` · `60,70` · `@120,0` · `F8` · `Z` `A`.
   대문자/소문자, 쉼표, 골뱅이, 부등호를 그대로 옮긴다. 학습자가 그대로 타이핑한다.
2. **규격을 지어내지 않는다.** 용지·도면틀·표제란·레이어·색·선 굵기·치수는
   대본과 `MASTER_DRAWING_SPEC.md` 에 있는 것만 쓴다.
3. **배점·제한시간·합격 기준은 채우지 않는다.** `note` 블록 `tone:"pend"` 로 자리만 잡는다.
4. **차시 경계를 넘지 않는다.** 다음 차시가 할 일을 미리 설명하지 않는다.
5. 명령을 가르칠 때마다 **현장에서 언제 쓰는지** 한 줄을 붙인다
   (지그 제안 / 레이아웃 확인 / 스페어 파트 공수). 대본에 있으면 그대로 쓴다.

## 4. JSON 구조

`content/lesson-0N.json` 하나를 UTF-8 로 쓴다. 아래 키만 쓴다.

```jsonc
{
  "no": 3,
  "slug": "lesson-03-baseline-profile",
  "title": {"ko":"기준선과 외곽", "en":"Baseline and Outline"},
  "videoLength": "38:17",
  "selfStudyMin": 55,
  "opens": "L02_TEMPLATE",          // 없으면 null
  "saves": "L03_PROFILE",           // 없으면 null

  "summary": {                      // 요약 탭 — CAD 지식 0 기준. 각 2~3문장.
    "what":  {"ko":"", "en":""},    // 이 차시에 무엇을 하는가
    "why":   {"ko":"", "en":""},    // 왜 지금 이걸 하는가
    "where": {"ko":"", "en":""}     // 부품이 지금 어디까지 그려져 있는가
  },
  "objectives": [{"ko":"", "en":""}],          // 3~5개. "…할 수 있습니다" 로 끝낸다
  "before": {
    "checklist": [{"ko":"", "en":""}],         // 시작 전 확인. 3~5개
    "recovery":  {"ko":"", "en":""}            // 앞 차시를 건너뛴 사람이 돌아오는 방법
  },

  "sections": [                                // 8~14개
    {
      "id": "origin",                          // 영문 슬러그
      "kind": "concept|onDrawing|practice",    // 탭 배치를 정한다
      "label": {"ko":"", "en":""},             // 대상의 이름. 「무엇인가」 같은 메타 레이블 금지
      "lede":  {"ko":"", "en":""},             // 한 문장. 없으면 생략 가능
      "blocks": [ ... ]                        // 아래 6종만
    }
  ],

  "verify": [ {"what":{"ko":"","en":""}, "how":{"ko":"","en":""}} ],
  "checks": [ {"q":{"ko":"","en":""}, "a":{"ko":"","en":""}} ],       // 4~6개
  "exercise": {
    "title": {"ko":"", "en":""},
    "body":  {"ko":"", "en":""},
    "criteria": [{"ko":"", "en":""}]
  },
  "shortcuts": [ {"key":"LINE", "name":{"ko":"","en":""}, "when":{"ko":"","en":""}} ],
  "recap": { "did":[{"ko":"","en":""}], "next":{"ko":"","en":""} }
}
```

### 블록 6종

```jsonc
{"type":"p",     "ko":"", "en":""}
{"type":"list",  "items":[{"ko":"","en":""}]}
{"type":"cards", "items":[{"label":{"ko":"","en":""}, "body":{"ko":"","en":""}}]}
{"type":"table", "caption":{"ko":"","en":""},
                 "head":[{"ko":"","en":""}],
                 "rows":[[{"ko":"","en":""}]]}
{"type":"note",  "tone":"why|warn|field|tip|pend",
                 "label":{"ko":"","en":""},          // 생략하면 tone 기본 레이블
                 "ko":"", "en":""}
{"type":"figure","id":"fig-...", "caption":{"ko":"","en":""},
                 "alt":{"ko":"","en":""}, "svg":"<svg …>…</svg>"}
{"type":"steps", "items":[
   {"n":1,
    "title":{"ko":"","en":""},
    "actions":[ {"type":"UCS", "do":{"ko":"입력하고 엔터를 누릅니다.","en":"then press Enter."}} ],
    "expect":{"ko":"","en":""},      // 이 단계가 끝나면 화면에 무엇이 보이는가
    "why":{"ko":"","en":""},         // 왜 이 순서·이 값인가
    "pitfall":{"ko":"","en":""}      // 안 되면 여기 — 증상과 복구
   }]}
```

- `actions[].type` 은 **실제로 타이핑하거나 누르는 값**이다. 클릭·확인만 하는 동작이면 생략한다.
- 본문 문자열 안에서 백틱으로 감싸면 명령 토큰으로 렌더된다: `` `LWDISPLAY` 를 켭니다 ``.
- `**강조**` 는 굵게 렌더된다. 그 밖의 마크다운은 쓰지 않는다. HTML 태그를 쓰지 않는다.

## 5. 그림

### 5-1. 부품 도면은 **직접 그리지 마라**

접선·필렛·탭 좌표를 손으로 맞추면 반드시 어긋난다. 정본 도면 셋이 이미 만들어져 있고,
`scripts/part/edu_ib_02.py` 가 `master-part-geometry.json` 과 같은 정의에서 그려 검산까지 마친 것이다.
`ref` 로 부르기만 한다.

| ref | 무엇 | 크기 | 쓸 자리 |
| --- | --- | --- | --- |
| `front` | 정면도 — 치수 없음, 중심선 있음 | 4.5 KB | 형상을 가리키며 설명할 때 |
| `frontdim` | 정면도 + 치수 전부 | 13 KB | 치수를 읽는 절, 7차시 |
| `three` | 제3각법 3뷰 + 치수 + 숨은선 | 16.5 KB | 투상 관계를 보일 때, 5차시 |

```jsonc
{"type":"figure", "ref":"front",
 "caption":{"ko":"정면도. 오늘 그리는 것은 베이스 외곽과 목입니다.","en":"Front view. Today you draw the base outline and the neck."},
 "alt":{"ko":"…그림을 못 보는 사람도 같은 정보를 얻게 쓴다","en":"…"}}
```

**한 차시에 `three` 는 최대 하나, `frontdim` 도 최대 하나다.** 용량이 크다.

### 5-2. 개념 도해만 직접 그린다

좌표 규칙, 절대/상대/극좌표의 차이, 제3각법의 배치 원리, 레이어 네 개의 선 모양처럼
**부품 형상이 아닌 것**은 직접 그린다. `svg` 키에 인라인으로 넣는다.

- `<svg viewBox="0 0 W H" width="W" height="H">` 형태. `xmlns` 는 생략해도 된다.
- **색을 직접 쓰지 않는다.** 아래 클래스만 쓴다. 라이트/다크가 자동으로 따라간다.

| 클래스 | 쓰임 |
| --- | --- |
| `si` | 외형선 — 굵은 실선 |
| `sh` | 강조 — 지금 설명 중인 형상 |
| `sd` | 보조선·치수선 — 가는 실선 |
| `sc` | 중심선 — 일점쇄선 |
| `sn` | 숨은선 — 파선 |
| `sl` / `slh` | 글자 / 강조 글자 |
| `sf` | 면 채우기 |

- 파선·쇄선 경로에는 `stroke-linecap="butt"` 를 준다. 둥근 캡은 dash 틈을 먹는다.
- 서로 닿는 요소는 최소 1 단위를 띄운다. 정확히 접하면 획 굵기 때문에 하나로 뭉친다.
- **제3각법 기호를 그린다면 방향을 확인한다.** 원뿔대의 **작은 끝이 원을 향한다.**
  뒤집으면 제1각법 기호이고, 투상법을 가르치는 그림이 정반대를 가르치게 된다.
- 좌표·치수는 `master-part-geometry.json` 과 `MASTER_DRAWING_SPEC.md` 값을 쓴다. 눈대중 금지.
- 폭 640 안쪽. 글자는 11px 이상.
- `alt` 는 그림을 못 보는 사람이 같은 정보를 얻을 수 있게 쓴다.

직접 그리는 개념 도해는 한 차시에 **1~3개**, 합계 8 KB 이하.
글로 충분한 것을 그림으로 만들지 않는다. 말로 하면 길어지는 것에만 쓴다.
`ref` 도면은 이 개수에 포함하지 않는다.

## 6. 분량

| 항목 | 한도 |
| --- | --- |
| **JSON 파일 크기** | **95 KB 이하** |
| 직접 그린 인라인 SVG 합계 | 8 KB 이하 (`ref` 도면은 별도) |
| 한 절의 블록 수 | 3~8개 |

**쪽 나누기는 네 일이 아니다.** 한 쪽에 다 안 들어가면 빌더가 「1부 개념 / 2부 실습」으로
알아서 나눈다. 그러니 **용량을 이유로 내용을 빼지 마라.** 설계서(`curriculum.json`)의
`sectionPlan` 에 있는 절은 전부 쓴다.

줄일 것은 문장의 길이지 내용의 개수다. 낭독을 위한 반복(「그렇습니다」 「다시 한번 보겠습니다」),
호흡을 위한 되풀이, 앞 문장을 바꿔 말한 문장은 **글에서는 군더더기다. 지운다.**
사실·치수·명령·예시는 하나도 빼지 않는다.

95 KB 를 넘으면 응답의 `droppedForSize` 에 **어느 절을 무엇 때문에 줄였는지** 적는다.
조용히 빼지 마라.

## 7. 다 쓰고 나서 — 반드시 실행한다

```bash
cd <SCRATCH>
python tools/validate_content.py content/lesson-0N.json
python tools/tone_check.py content/lesson-0N.json
```

**둘 다 PASS 가 될 때까지 고친다.** 한 번 돌리고 끝내지 마라.

`validate_content.py` 가 보는 것
- JSON 파싱 · 필수 키 · 블록 유형
- 영문이 빈 쌍, 국영 길이가 심하게 어긋난 곳
- 산문에 HTML 태그가 섞였는지
- **타이핑 값이 원본 `SCRIPT.md` 의 백틱 안에 실제로 있었는지** — 여기 경고가 뜨면
  네가 명령을 지어냈거나 표기를 바꾼 것이다. 원본을 다시 확인해 고친다
- 파일 크기

`tone_check.py` 가 FAIL 이면
- 합쇼체가 80% 초과 → 사실 진술 몇 개를 되묻기·부연으로 바꾼다
- 70% 미만 → 해요체 부연을 합쇼체로 되돌린다
- 문어체가 하나라도 잡히면 전부 고친다 (경로가 출력된다)

`tone_check.py` 가 **PASS** 가 아니면 고쳐서 다시 돌린다. 합쇼체가 80%를 넘으면
사실 진술 몇 개를 되묻기·부연으로 바꾸고, 70% 아래면 해요체 부연을 합쇼체로 되돌린다.
문어체가 하나라도 잡히면 전부 고친다.

최종 응답에는 파일 경로, 절 개수, 단계 개수, 도해 개수, tone_check 결과 수치만 담는다.
본문을 응답에 복사하지 않는다.

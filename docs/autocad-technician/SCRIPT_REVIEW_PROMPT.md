# 강의 대본 검토 프롬프트

다른 AI에게 국문·영문 대본이 **말로 들었을 때** 자연스러운지 물을 때 쓰는
프롬프트다. 그대로 복사해 붙이고, 아래 「무엇을 첨부하나」대로 파일을 올린다.

대본은 읽는 글이 아니라 **낭독되는 글**이다. 그래서 검토 기준이 문서 교정과
다르다 — 한 호흡에 읽히는지, TTS가 끊어 읽을 자리가 있는지, 숫자와 명령어가
소리로 구별되는지가 핵심이다. 프롬프트가 그 기준을 먼저 못 박지 않으면
맞춤법 지적만 돌아온다.

## 무엇을 첨부하나

- 국문 대본 8개 — `AutoCAD_Scripts_KO_*.zip` (릴리즈 첨부)
- 영문 대본 8개 — `AutoCAD_Scripts_EN_*.zip`
- 한 번에 다 올리기 어려우면 **차시 하나씩**, 국문·영문을 짝으로 올린다.

## 복사해 쓰는 프롬프트

```text
당신은 기업 교육용 영상 강의의 대본을 검토하는 편집자입니다.
아래 규칙을 먼저 읽고, 첨부한 대본을 검토해 주세요.

# 이 대본이 무엇인가

AutoCAD 2024 실습 강의 8차시의 낭독 대본입니다. 사내 기술직 인증 과정이고,
듣는 사람은 제도를 처음 배우는 설비 담당자입니다. 차시당 영상 하나이며
길이는 국문 27~31분, 영문 30~36분입니다.

**이 글은 읽는 글이 아니라 소리 내어 읽히는 글입니다.** 사람이 아니라 TTS가
읽습니다.

  · 국문 — Windows SAPI, Microsoft Heami, 원본 속도에 1.38배 (음높이 보존)
  · 영문 — Windows SAPI, Microsoft Zira, 1.15배

화면에는 슬라이드가 함께 흐르고, 문단 하나가 화면의 한 항목과 짝지어져 있습니다.

# 무엇을 봐 달라는 것인가

**소리로 들었을 때 자연스러운가**만 봐 주세요. 우선순위 순입니다.

1. **호흡** — 한 문장이 한 호흡에 읽히는가. 1.38배로 읽으면 긴 문장은
   숨 쉴 자리가 없어 뭉개집니다. 접속사로 이어 붙인 문장, 관형절이 겹친 문장.
2. **TTS가 틀리게 읽을 자리** — 숫자·단위·기호·영문 약어가 섞인 대목.
   「Ø25」 「2-C5」 「R10」 「4-M5」 같은 표기, 한글 속 영문(LINE, TRIM),
   동음이의(「사분점」/「사분면」, 「도면층」/「도면 층」) 같은 것.
3. **입으로 굴러가는가** — 같은 조사·어미가 연달아 오는 대목, 발음이 겹쳐
   혀가 꼬이는 대목, 세 번 이상 반복되는 문장 구조.
4. **듣는 사람이 따라오는가** — 앞을 안 듣고 온 사람도 이 문단만으로 무엇을
   하라는 것인지 아는가. 지시대명사(「그것」 「거기」)가 가리키는 것이 소리만
   듣고 잡히는가.
5. **말투가 한 사람의 것인가** — 같은 차시 안에서 존대/설명체가 흔들리는가.

영문은 위에 더해 이것도 봐 주세요.

6. 원어민이 소리 내어 읽었을 때 어색한 어순·관사·전치사.
7. 국문 문장을 그대로 옮겨 영어로는 부자연스러워진 자리.
8. 다만 **국문보다 짧거나 길어지는 것 자체는 문제가 아닙니다.** 문단 수만
   같으면 됩니다(아래 제약 참조).

# 절대 바꾸면 안 되는 것

대본은 화면·음성과 기계적으로 묶여 있습니다. 아래를 건드리면 강의가 깨집니다.

- **문단 수.** 4칸 들여쓴 줄 묶음 하나가 문단 하나이고, 국문과 영문의 문단
  수가 Line마다 정확히 같아야 합니다. 문단을 합치거나 나누지 마세요.
  문단 안에서 문장을 고치는 것은 됩니다.
- **문단 첫머리의 `(1 …)` `(2행 …)` 같은 괄호 번호.** 화면의 몇 번째 항목을
  가리키는 표식입니다. 번호와 순서를 그대로 두세요.
- **백틱 안의 값** — `REC` `120` `0.5` `Visible line`. 학습자가 키보드로
  실제로 치는 값입니다. 한 글자도 바꾸지 마세요.
- **`## Line N` 과 `### 3단계` / `### Step 3` 제목**, `**Time:**` 줄.
- **치수·기호** — `Ø25 H7` `2-R10` `PCD Ø44` 같은 도면 표기.
- **용어** — 외형선/visible line, 장공/slot, 정면도/front view 등은 과정
  표준으로 고정돼 있습니다. 더 나은 말이 있어도 바꾸지 말고, 정말 문제가
  있다면 따로 「용어 의견」으로만 적어 주세요.

# 어떻게 답해 달라

고칠 자리마다 아래 일곱 칸을 채워 주세요. **표나 목록으로, 한 줄에 하나씩.**

  파일 | Line | 문단번호 | 심각도 | 원문(그대로) | 제안(그대로) | 이유(한 줄)

- 문단번호는 그 Line 안에서 몇 번째 문단인지 셉니다(1부터).
- 원문과 제안은 **앞뒤를 자르지 말고 문장 통째로** 적어 주세요. 그대로
  찾아 바꿀 수 있어야 합니다.
- 심각도는 셋 중 하나: `높음`(듣는 사람이 못 알아듣거나 TTS가 틀리게 읽음) /
  `보통`(어색하지만 뜻은 통함) / `낮음`(취향 차이).
- 이유는 한 줄이면 됩니다. 「길어서 호흡이 안 됨」 「숫자 앞에서 끊김」처럼.

마지막에 이것도 붙여 주세요.

  · 차시별로 가장 자주 나온 문제 유형 한두 개.
  · `높음`만 따로 모은 목록.
  · 국문과 영문 중 어느 쪽이 더 손이 필요한지, 왜 그런지 세 줄 이내.

# 하지 말아 달라

- 전체를 다시 쓰지 마세요. 고칠 자리만 짚어 주세요.
- 문장을 무조건 짧게 만들지 마세요. 설명이 필요한 대목은 길어도 됩니다.
  「한 호흡에 읽히는가」가 기준이지 글자 수가 기준이 아닙니다.
- 내용의 정확성(제도 규칙·AutoCAD 동작)은 검토 대상이 아닙니다. 다만
  **명백히 틀린 것**이 보이면 맨 끝에 「내용 의문」으로 따로 적어 주세요.
- 잘 쓰인 대목을 칭찬하는 데 분량을 쓰지 마세요.
```

## 돌려받은 뒤

제안은 **문단 안에서만** 반영한다. 문단 수가 하나라도 달라지면
`scripts/part/test_script_editions.py` 가 그 차시를 잡는다 — 국문과 영문의
Line·문단·비트 번호가 같은지 검사한다. 반영 뒤에는 이것부터 돌린다.

```bash
python -m unittest discover -s scripts/part -p 'test_script_editions.py'
```

음성은 대본이 바뀌면 다시 합성해야 하고(`narrate_tts.py`), 프레임 시각도
다시 맞춰야 한다(`retime_frames.py`). 그 순서는 `docs/HANDOFF.md` 의
「영문 강의를 만드는 길」에 있다.

자습 시간 836분(약 13.9시간)은 이렇게 나왔습니다 How the 836-minute estimate was derived

영상 러닝타임에 배수를 곱한 값이 아닙니다. 자습본이 실제로 담을 항목 수를 세어 다시 계산했습니다. 네 가지를 더합니다. ① 읽기 = 개념 절 수 × 40초 (본문 30초 + 도해·표 대조 10초). ② 따라 하기 = 조작 항목 수 × 25초 + 조작 단계 수 × 90초. 조작 항목 하나는 명령 입력·좌표 입력·클릭·대화상자 선택 하나입니다. 25초의 근거는 3·4차시 녹화 예상 길이 20분 10초를 그 차시 조작 항목 수 108개·96개로 나눈 강사 페이스 약 11~13초이고, 자습자는 지시를 읽고 화면을 옮기고 입력한 뒤 결과를 대조하는 왕복을 혼자 하므로 두 배로 잡았습니다. 90초는 단계마다 붙는 「왜 이렇게 하나 / 이렇게 되면 맞습니다 / 안 되면 여기를 보세요」를 읽고 화면과 맞추는 시간입니다. ③ 검산 = 검산 항목 수 × 90초. DI·LIST·QSELECT·레이어 껐다 켜기는 명령을 실제로 쳐야 값이 나오므로 읽기 시간이 아닙니다. ④ 마무리 = 차시당 5분 (단축키 표 훑기, 체크포인트 파일 저장 확인). 8차시에는 40분 모의 작도 1회를 따로 더했습니다. 차시별 값은 28 · 130 · 107 · 100 · 144 · 93 · 137 · 97분이고 합계 836분 = 13.9시간입니다. 영상 264분의 3.2배입니다. 배수가 아니라 항목 수에서 나온 값이므로 집필 중 절이 늘거나 줄면 같은 식으로 다시 계산합니다. 영상 길이 자체가 추정치(실측 나레이션이 들어오면 바뀜)이므로 이 값도 확정값처럼 쓰지 않습니다.

This is not the video runtime multiplied by a factor. It is recalculated from a count of what the workbook will actually contain. Four terms add up. (1) Reading = number of concept sections x 40 s (30 s of text plus 10 s checking it against the diagram or table). (2) Hands-on = number of operation items x 25 s + number of operation steps x 90 s. One operation item is a single command entry, coordinate entry, click, or dialog choice. The 25 s comes from the estimated recording length of Lessons 3 and 4 (20 min 10 s) divided by their operation-item counts (108 and 96), which gives an instructor pace of roughly 11-13 s; a self-study learner reads the instruction, switches windows, types, and checks the result alone, so the figure is doubled. The 90 s per step covers reading the 'why this way / this is what correct looks like / if it did not work, look here' block and matching it against the screen. (3) Cross-check = number of check items x 90 s, because DIST, LIST, QSELECT, and toggling layers all require actually running a command. (4) Wrap-up = 5 min per lesson (skimming the shortcut table, confirming the checkpoint file saved). Lesson 8 adds one 40-minute timed mock drawing. Per lesson: 28, 130, 107, 100, 144, 93, 137, 97 minutes; total 836 minutes = 13.9 hours, which is 3.2x the 264 minutes of video. Because the figure comes from item counts rather than a multiplier, recompute it the same way if sections are added or removed during writing. The video lengths are themselves estimates that will change once measured narration arrives, so do not present this number as settled either.

Ten self-contained HTML files: one index, eight lessons, and one shared shell (color, type, tables, diagram styles, script). The shell lives in one place and each lesson pulls it in - never copied. A page reads top to bottom like this. (1) Header - title, written and updated timestamps, and a checkpoint badge showing the file you open and the file you save. The badge stays pinned while you scroll. (2) Left-hand section list - section name plus estimated minutes. The current section is highlighted and finished ones dim slightly: the video's three reading states rendered as static hierarchy rather than animation, with the contrast kept low. A checkbox beside each section is the reader's own progress mark, stored in localStorage under a filename key with a memory fallback. (3) Body - no section longer than about one screen. Each operation step is a four-column row: what you type, what it asks, what you enter, what correct looks like. Below it sits a collapsed 'if it did not work, look here' block: symptom, cause, fix on the spot, and which step to return to if that fails. Collapsed, it does not interrupt a reader for whom everything is working. (4) A stop point ends every section - one line of judgement plus 'this is a good place to stop'. The button to the next section sits under that judgement, never above it. (5) Footer - previous and next lesson, and a link to this lesson's recovery note. A memo sidebar is pinned on the right, collapsed by default and overlaid rather than pushing the text: drag-select, click the floating Memo button, and the quotation is pinned; major blocks carry data-memo anchors. 'Copy memo as prompt' assembles quotation, location, and note. The Korean/English toggle sits at the top right and switches the whole document at once - both languages live in the same DOM, switched by data-lang, with the choice remembered in localStorage. A build check compares node counts between the two languages so no section ships half-translated; diagram labels carry both languages too. Printing hides the toggle, the section list, the memo sidebar, and the top banner, and expands every collapsed recovery block - some people will carry paper to the machine. No external libraries, no build step, no network: CSS, JS, and SVG are all inline. No more than three colors: text #111111, secondary #666666 and #A4A3A4, accent #C7004C, page #FFFFFF, surface #F5F5F3, rules #A4A3A4. Zero corner radius, 2 px borders, no shadows. Light and dark switch automatically, with aria roles, contrast, and visible focus throughout.

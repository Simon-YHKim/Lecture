### 뿌리를 잡은 결함 셋 — 다음에 또 걸린다

**1. `<use>` 는 viewBox 원점을 안 받는다.** x/y 를 안 주면 (0,0) 에 놓인다. 정면도의
viewBox 는 `48 108 140 110` 이라 도면이 화면 밖으로 밀렸고, **원점이 0 인 삼면도·A3 만
멀쩡히 보였다.** 그래서 이전 점검이 통과했다 — 눈으로 본 표본이 하필 원점 0 이었다.

```python
def use_tag(sid, svg):                      # coach.py
    x, y, w, h = viewbox(svg).split()
    return '<use href="#%s" x="%s" y="%s" width="%s" height="%s"/>' % (sid, x, y, w, h)
```

**2. 노트를 그 장이 담은 것에서 만들지 않았다.** 두 군데가 같은 병이다.

    개념 절  나뉜 모든 장에 절의 lede 를 그대로 붙였다. 2/4·3/4·4/4 가 1/4 과
             똑같은 한 줄을 가졌고, **빈 노트가 아니라 같은 노트**여서 빈 노트
             검사에도 안 걸렸다.
    실습 절  노트를 `expect` 와 `why` 에서만 만들어, 단계를 나누면 그 둘이 첫 장과
             끝 장에만 남고 가운데 **마흔 장**이 비었다.

**3. 산문과 치는 값이 따로 놀았다.** 선가중치를 0.30/0.15 로 고칠 때 산문만 고치고
`actions[].type` 은 `0.50`·`0.25` 로 남겼다. 사용자 메모 7번이 「뒤쪽 실습과 숫자를
맞추자」고 한 그 자리다. **학습자가 실제로 치는 것은 후자다.**

### 이번에 배운 것 넷 — 다음에 또 걸린다

**1. `<use>` 안쪽은 바깥 CSS 가 닿지 않는다.** 클래스만 두고 CSS 에 맡기면 채우기가
기본값(검정)으로 남아 A3 도면틀이 **까만 상자**로 나온다. 해법이 둘이고 쓰는 자리가
다르다.

    자습 교재  `<symbol>` 안에 `<style>` 을 넣는다 — 함께 복제되어 적용된다.
               파일이 작다 (정면도 19KB → 14KB · 세 뷰 42KB → 26KB)
    묶음 데크  속성으로 박는다 — `<use>` 가 여든두 개라 `<style>` 도 여든두 번
               복제·파싱된다

**2. 강조를 먼저 켜고 나서 표현을 박는다.** 순서가 바뀌면 stylize 가 class 뒤에
속성을 끼워 넣어 `class="hl" data-feature=` 짝이 깨지고 강조가 조용히 안 켜진다.

**3. 쪽 나누기 예산에서 도해 몫을 빼야 한다.** 안 빼면 담을 때는 들어갔다가 낼 때
넘친다. 절 하나가 예산을 통째로 넘으면 쪽 나누기가 할 수 있는 일이 없으므로,
**단계 경계에서 절을 나누는** 길도 함께 열어 뒀다 (`render_section_split`).

**4. 표시 크기는 자리 간격으로 정한다.** 평면도는 깊이가 20 밖에 안 돼서 앞면·
판앞면·뒷면 세 자리를 같은 크기로 찍으면 고리 셋이 겹쳐 구별이 안 된다.

### 도구가 틀렸던 것 셋 — 다음에 또 걸린다

1. **`.motion.json` 이 프레임을 따라오지 않았다.** 같은 길이를 HTML 과 JSON 두
   곳에 적는 구조라 한쪽만 고치면 반드시 어긋난다. `retime_frames` 가 프레임을
   쓸 때 함께 쓰게 했다. **맞출 트윈이 없는 프레임(인사·녹화)도 길이는 바뀐다** —
   일찍 빠져나가던 자리에서도 쓰게 했다.
2. **녹화 프레임의 단계 띠가 통째로 밀려 있었다.** `narrate_tts` 는 `(N …)` 표식이
   붙은 문단만 비트로 적는데 녹화는 `### N단계` 를 쓴다. 잰 비트가 하나도 없어
   `retime_frames` 가 그 프레임을 건너뛰었다. 검사기가 쓰는 것과 **같은 계산**
   (`beats.plan`)을 retimer 도 쓰게 했다 — `planned_spans()`.
3. **`beats.measured_plan` 이 박자를 뒤로 밀었다.** 잰 비트 사이에 표식 없는
   문단이 여럿이면 각각 다음 비트의 시작 시각을 받은 뒤 최소 0.8초씩 패딩되어,
   다음 비트가 문단 수 × 0.8초만큼 밀렸다. 2차시 마무리가 2.4초를 그렇게 잃었고
   검사기는 **아무도 말하지 않는 자리에서 모션을 요구**했다. 문단 묶음이 두 비트
   **사이를 나눠 갖게** 고쳤다.

이름이 번호로 끝나지 않는 계열(`.p-done`/`.p-next`, `.sh-paper`/`.sh-frame`)은

**함정 둘 (교재 쪽)**

- **`<use>` 안쪽은 바깥 CSS 가 닿지 않는다.** 클래스만 두고 CSS 에 맡기면 채우기가

- **강조를 먼저 켜고 나서 stylize 한다.** 순서가 바뀌면 stylize 가 class 뒤에
  속성을 끼워 넣어 `class="hl" data-feature=` 짝이 깨지고 강조가 안 켜진다.
- 한 쪽 100KB 한도 때문에 도해는 쪽마다 `<symbol>` 한 벌만 두고 `<use>` 로 부른다.
  **쪽 나누기 예산에서 그 한 벌 몫을 빼야 한다** — 안 빼면 담을 때는 들어갔다가

### 적용 중인 정책 (영구 — 사용자가 명시한 것)

1. **좌표 입력 금지.** "좌표를 이용한 작업은 권장하지 않음. 너무 어렵고 불편한 방법임.
   마우스와 키보드를 이용해서 작업하는게 훨씬 직관적. 모든 강좌에서 이런방식으로
   설명해야 함." → 마우스 커서 + 스냅 + 수치입력. 예외는 용지선 두 구석(`0,0`,`420,297`).
2. **작도 실습 슬라이드에는 도면 + 코치 마크 + 지금 그리는 요소 강조.** 점검 카드는
   최하단 한 행으로 내리고 그 자리에 도면을 띄운다. 코치 마크는 슬라이드마다 지시하는
   작업이 다르면 함께 바뀌어야 한다.
3. **윈도우(좌→우) / 크로싱(우→좌) 선택의 차이를 설명한다.**
4. **박스 중심 텍스트** — 박스에 X 사선을 긋고, DTEXT 정렬을 중간-센터로 해서 교차점에
   스냅한 뒤, X 를 지운다.
5. **슬라이드 아래 빈 공간 금지.** "전 슬라이드에 걸쳐서 이런 현상이 발생하지 않도록
   명심해. 다른 슬라이드에 대해서는 별도 언급하지 않을테니 전수 검사해서 개선해."
6. **문체** — 합쇼체 70~80% / 해요체 20~30%.
7. **디테일한 키 입력 규제보다 방법을 알려주는 데 초점.**
8. **검수 HTML 은 다운로드 가능한 단일 파일.** 사용자는 아티팩트를 못 보는 환경이다.

### 이 저장소의 함정 (겪은 것만)

- **셸 히어독이 이스케이프를 먹는다.** `\n`, `\\`, `\s` 가 한 번 더 풀려 파이썬·JS
  소스가 깨진다. 이스케이프가 있는 것은 **반드시 Write/Edit 도구로** 쓴다.
  이번 세션에도 두 번 당했다.
- **KST 시각은 PowerShell 로.** Git Bash 의 `TZ=Asia/Seoul date` 는 이 머신에서
  9시간 이르다. `powershell.exe -NoProfile -Command "Get-Date"`.
- **`private-materials-guard` 는 사용자 폴더를 가리키는 로컬 절대 경로를 막는다.**
  `file:` 스킴으로 시작하는 윈도우 사용자 폴더 경로가 대표적이다. 공개 저장소에
  개인 경로가 남는 것을 막는 규칙이라 맞는 동작이고, **이 문서에 그 형태를 예시로
  적어도 걸린다**(직접 겪었다). 도구 스크립트는 경로를 런타임에 찾아야 한다 —
  `scripts/selfstudy/audit/pw.mjs` 가 그 방법이다.
- **자습본 빌드는 `BUILD_STAMP` 가 필요하다.** 없으면 헤더 작성 시각이 빈칸으로
  나간다(`작성  · 발행 Claude Code`). 실제로 그렇게 나간 파일이 있다.
  `BUILD_STAMP='YYYY-MM-DD HH:MM KST' python scripts/selfstudy/build_selfstudy.py …`
- **`.playwright-mcp/` 는 `.gitignore` 에 없다.** 86파일 1.1MB 의 검수 흔적이다.
  작업물을 커밋하기 전에 무시 목록에 넣을 것.
- **SCRIPT.md 는 문장마다 줄을 나누고 네 칸을 들여 쓴다.** 여러 문장을 한 덩어리로
  바꾸려 하면 안 맞는다. **문단이 교체 단위**이고 앞에 `'    '` 를 붙인다.
- **데크 화면을 눈으로 확인할 때는 장면을 이름으로 집는다.** 데크는 장면을 겹쳐 두고
  투명도로만 가리므로 "폭이 0 아닌 첫 장면"은 엉뚱한 장을 집는다. 이것 때문에
  한 시간을 헤맸다.
